设计说明（预览右侧面板的多种真实场景）

1. 布局结构：分支按钮 + 右侧独立状态徽标
  • 将原先单个 .git-branch 按钮包入横向 flex 容器 .git-branch-row。
  • 左侧 .git-branch 保持「点击复制分支名」，设 flex: 0 1 auto; min-width: 0 —— 分支名过长时只省略分支名，不会把右侧指示器挤出或折行。
  • 右侧徽标设 flex: none，不参与复制分支，鼠标悬停（title）展示详细构成（如：3 个未提交文件：2 修改 · 1 未跟踪）。
2. 三种候选样式对比（可在顶部下拉框切换体验）
  • 方案 A（推荐）：未提交显示 ● 3（暖色圆点+数字），已提交显示柔和 ✓。仅占 ~34px，极长分支下最稳，纯黑/纯白主题下也能一眼区分。
  • 方案 B：未提交显示 ● 3 未提交，已提交显示 ✓ 已提交。语义零门槛，但占用 ~70px，分支稍长就会被省略。
  • 方案 C：仅在有未提交时显示 ● 3，干净时不显示。最极简，但无法区分「干净」与「未检查」。
3. 边界处理与性能约束
  • 未知/读取失败：显示虚线 —（或隐藏），绝不误报为 ✓ 干净。
  • 新 init 尚无提交：若目录已有文件，照常统计未跟踪文件数（如 ● 4），下方仍保留「尚无提交」。
  • 采集方式：主进程按需执行 git status --porcelain=v1 -z -unormal 统计条目（不读取文件内容、不递归监听工作树，仅在面板展开/聚焦/定期校验时刷新）。
